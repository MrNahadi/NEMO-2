\chapter{Project workplan}
\label{chap:workplan}

This chapter gives the project schedule from September 2026 to March 2027. It
covers both phases. The first phase built \NEMO{}~1 and found its limits. The
second phase rebuilt the tool as \NEMO{}~2 and is the subject of this report.

\section{Schedule}
\label{sec:schedule}

Figure~\ref{fig:gantt} shows the schedule. September and October were spent on the first phase. It covered the literature, the first bracket model, the Fusion proof
of concept, the sampling and optimisation code and the first versions of the
padeye and fin. The review at the end of October found that the Fusion
Simulation step could not be automated and that two of the bracket studies had
to be rejected. It led to the decision to rebuild the tool with its own
analysis pipeline.

The second phase started in November with the engine core and the padeye,
built end to end, followed in December by the finite element pipeline, the
local server and the browser application. The pipe support bracket and the
stabilizer fin were added in January, together with the verification suite.
February is given to the case studies, the parameter sweeps, the documentation
and the installer, and to the tests still outstanding. These are a live run of the Fusion
connector, a Fusion stress cross-check, a comparison with a published BTH-1
worked example and a small usability study with students who have not used the
tool. March is reserved for corrections, the demonstration and submission.
Report writing runs through the whole project, because decisions and evidence
were recorded as the work went on.

\section{Workplan review}
\label{sec:workplan-review}

The main change to the plan was the rebuild. It cost the time spent on the
first phase's Fusion bridge and its stress studies, but it removed the manual
step that had blocked the first phase. Building the padeye end to end before
the other parts also paid back. When the bracket and the fin were added in
January, the check record, the sizing pattern, the finite element pipeline,
the run log and the report generator were already in place and tested.

The outstanding tests in February depend on things outside the code, namely a Fusion session, a published worked example and volunteers for the usability study.
If any of them slips, it does not hold up the rest of the work, because the
engine, the application and the case studies are complete. Any test that is
not finished by submission will be reported as future work.
